# Roadmap

[Back to the README](../README.md) · [Evidence and relevance](evidence-and-relevance.md)

BlueTeam.News helps a single analyst or security lead follow public threat
reporting, inspect supporting passages, and prepare an assessment. The next
priority is to carry that work through a reviewed decision and handoff.

These are proposed directions, not delivery commitments. Scope and order may
change; there is no promised release date or maintenance schedule. See
[Support](../SUPPORT.md) for the project's support boundaries.

## Available today

- A declared watch profile explains literal technology, sector, and region
  matches while keeping local exposure unknown.
- Wire retains bounded source excerpts and their observation history, preserves
  publisher attribution, and shows changes between retained revisions.
- Briefing uses the latest collection selection and records the supplied
  evidence, configuration, provider attempts, and validation results beside
  each new edition. Older editions can lack these receipts.
- Wall and Print Edition present saved assessments and their cited sources.

A source group is not a persistent situation, a profile match is not an exposure
check, and a generated assessment is not an analyst-approved decision. Wire
filters and hidden items do not curate the next Briefing's inputs. Read
[Evidence and relevance](evidence-and-relevance.md) for the current workflow,
retention rules, and verification limits.

## Proposed priorities

| Priority | Improvement | What successful use would make possible |
|---|---|---|
| 1 | Persistent situations and analyst decisions | Reopen yesterday's issue with its evidence, unresolved applicability questions, disposition, owner, and next action intact. |
| 2 | Explicit Briefing input selection | Choose a focused evidence set, review that selection, and know exactly which sources will be supplied before generation. |
| 3 | Reviewed handoffs and completion records | Distinguish a draft from an approved assessment, record acknowledgment, and track the evidence needed to close an action. |
| 4 | Evidence and ranking evaluation | Test source attribution, contradictions, material omissions, and ranking against reviewed cases, with visible uncertainty and measured limits. |
| 5 | Operator-controlled retention and sharing | Make retention choices and source handling restrictions visible before exporting or redistributing working evidence. |

The first acceptance scenario is a vendor advisory that changes the next day:
retain the earlier assessment, surface the revised passage, reopen the affected
applicability decision, and carry a reviewed next step into the handoff. Current
source history and generation receipts provide part of that foundation; the
analyst decision and completion workflow remains future work.

## Scope

The project remains a source-installed, self-hosted application for one trusted
operator. A hosted multi-user service, asset-inventory integration, automatic
remediation, and a bundled installer are outside the current release scope.
Focused bug reports are welcome under [Support](../SUPPORT.md); the project does
not accept unsolicited feature requests or pull requests. See
[Contributing](../CONTRIBUTING.md) for details.
